# 自贡农商银行法治合规短视频竞赛活动 需求与规格说明书

## 1. 项目背景与定位
- **活动全称**：自贡农商银行法治合规短视频竞赛活动
- **活动主题与官方介绍**：
  > 按照合规文化建设实施方案要求，以合规为主题，聚焦合规管理、风险管理、案件防控、员工行为管理等日常重点，以案为鉴，体现业务经营热点、难点，有效警醒和入脑入心，市行组织法治合规视频竞赛活动，在各一级支行的热情参与下，现已完成视频征集，快来为你最喜欢的优秀作品投票吧！
- **业务定位**：
  面向自贡农商银行全体员工及社会公众的短视频展播与组织化评选系统。系统兼顾移动端/PC端高清视频观摩、一人一票实名投票，以及市行管理后台对各一级支行组织动员成效的交叉透视统计与数据导出。

---

## 2. 核心架构与技术选型

### 2.1 整体架构
- **系统形态**：单页前后端分离应用（SPA），前端通过路由区分大众投票端 (`/`) 与 管理后台 (`/admin`)。
- **前端技术栈**：Vue 3 + Vite + TailwindCSS + Pinia + Vue Router + Chart.js + @fingerprintjs/fingerprintjs。
- **后端技术栈**：Python 3.10+ + FastAPI + Uvicorn + SQLite 3 (WAL模式) + PyJWT + openpyxl。
- **部署模式**：Docker 容器化多阶段构建，单服务镜像统一托管前端静态页面与后端 API，宿主机映射端口 `8090`。
- **网络与CDN加速**：
  - 域名由 Cloudflare 代理，自动支持静态 MP4 视频边缘缓存与 HTTP Range（206 Partial Content）分段快播。
  - 宿主机 Nginx 负责反向代理与域名分流，透传真实客户端 IP (`CF-Connecting-IP`)。
  - 数据与视频存储采用 Docker Volume 持久化绑定挂载（`data/voting.db` 与 `docs/videos/`）。

## 3. 功能模块详细需求

### 3.1 用户端（公众投票端，路由: `/`）
1. **活动主视觉与氛围**：
   - 响应式布局：完美适配移动端（微信内置浏览器/手机浏览器）与 PC 端大屏。
   - 展现官方活动标题、合规文化介绍、投票倒计时以及一人一票规则说明。
2. **作品网格与展播卡片**：
   - 展示 5 个参赛短视频（分辨率 960×544，H.264 编码，存放于 `docs/videos/1.mp4` ~ `5.mp4`）。
   - 作品封面与初始数据：
     * 作品 1：《“九五”普法宣传——远离非法助贷陷阱，守住自身财产安全》（尊法合规·金融为民）
     * 作品 2：《网点合规微短剧》（柜面风险防控与合规经办）
     * 作品 3：《筑牢金融“铁围栏” 守住百姓“钱袋子”》（荣县支行）
     * 作品 4：《防范非法集资与反诈宣传微短剧》（守护银龄财产安全）
     * 作品 5：《合规无小事——保护客户信息，守住职业底线》（市行合规案例剖析）
   - 每张卡片包含：视频封面、作品名称/选送支行、作品简介、累计得票数、专属【为 Ta 投票】按钮。
3. **模态浮窗播放器（Modal Video Player）**：
   - 点击作品封面或播放按钮，弹出沉浸式暗色模态浮窗。
   - 原生 HTML5 播放器，支持全屏、倍速、清晰进度条拖拽与 HTTP Range 毫秒级跳播。
   - 弹窗底部展示完整作品简介，并提供浮窗内直接【投 Ta 一票】便捷操作。
   - 窗口关闭时自动暂停视频并释放资源，避免后台流量损耗。
4. **一人一票与信息录入弹窗**：
   - **投票规则：一人一票制**，每位用户在整个活动期间只能投出唯一的一票，提交后不可撤回或重复投票。
   - 点击任意作品的【为 Ta 投票】按钮后，**弹出实名及归属信息确认弹窗**：
     - **投票意向确认**：明确展示当前选择支持的作品标题与选送支行。
     - **所属单位/支行选择**：下拉菜单选择所属支行或机关部室（数据来自管理后台配置的一级支行列表）。
     - **投票人姓名输入**：输入真实姓名（文本输入框，必填）。
   - 点击【确认投票】发起提交，提交内容包含候选作品 ID、单位 ID、姓名与设备指纹。
   - 投票成功后，界面即时高亮已投作品，全场所有作品的投票按钮变为“已投票”并禁用，展示最新票数与动态排行。
5. **多重反作弊与防刷机制**：
   - **设备指纹维度**：集成 FingerprintJS 采集浏览器环境哈希（Visitor ID），严格限制单设备只能投 1 次。
   - **实名单位防重**：同一单位下的同姓名用户仅允许投 1 票，防止同一个人换设备或换浏览器重复投票。
   - **真实 IP 维度**：后端严格解析 `CF-Connecting-IP` / `X-Forwarded-For`，同 IP 每日达到上限阈值后拦截。

### 3.2 管理端（运营管理后台，路由: `/admin`）
1. **管理员鉴权**：
   - 独立登录页，采用预设管理员账号与密码登录，基于 JWT Token 无状态鉴权。
2. **数据大屏与实时看板（Dashboard）**：
   - 核心统计指标：累计总票数、独立参与人次、独立 IP 数、领跑作品。
   - 票数分布与排行榜：动态柱状图/占比环形图（Chart.js），直观呈现 5 个作品得票阶梯。
3. **各一级支行/单位管理**：
   - 预置自贡农商银行各一级支行（荣县支行、富顺支行、自流井支行、贡井支行、大安支行、沿滩支行、高新支行、市行机关等）。
   - 支持新增支行、修改名称、调整排序权重与启停用。
4. **支行投票交叉透视分析（重点）**：
   - **透视矩阵表**：表格交叉展示“一级支行 × 参赛作品”得票数据，清晰洞察各支行分别给哪些作品投了多少票。
   - **来源构成分析**：点击任意候选作品，查看该作品得票的支行来源占比环形图。
5. **候选作品管理（CRUD）**：
   - 查看所有作品详情：ID、标题、选送支行/部门、封面、视频地址、当前得票、展示状态。
   - 支持在线编辑作品标题、作者与介绍内容，支持调整作品上下架状态与展示排序。
6. **活动规则与安全配置**：
   - 一键开启/暂停整个投票活动。
   - 配置活动开始时间与截止时间窗口。
   - 配置同 IP 每日投票防刷阈值。
7. **投票日志审计与作弊治理**：
   - 投票明细流水表：时间戳、所属支行/单位、投票人姓名、客户端真实 IP、设备指纹 Visitor ID、所投候选人。
   - 防刷治理：支持按异常 IP、设备指纹或姓名检索，并支持“一键作废作弊票”，自动扣减对应作品票数。
8. **多维度数据报表导出**：
   - 一键导出标准多 Sheet 的 Excel 文件：
     - Sheet 1: 作品总票数与最终排名表。
     - Sheet 2: 各一级支行投票透视矩阵表（支行 × 视频得票数）。
     - Sheet 3: 完整实名投票明细流水日志（含时间、所属支行、姓名、所投作品、IP、设备号）。

## 4. 数据库设计 (SQLite 3)

### 4.1 候选作品表 (`candidates`)
- `id`: INTEGER PRIMARY KEY AUTOINCREMENT
- `title`: TEXT NOT NULL (作品名称)
- `subtitle`: TEXT (选送支行/作者)
- `description`: TEXT (作品详细介绍)
- `video_url`: TEXT NOT NULL (对应 `docs/videos/1.mp4` ~ `5.mp4`)
- `cover_url`: TEXT (封面图片路径)
- `votes`: INTEGER DEFAULT 0 (累计总得票数)
- `display_order`: INTEGER DEFAULT 0 (展示排序序号)
- `is_active`: INTEGER DEFAULT 1 (1:启用, 0:下架)

### 4.2 单位/支行配置表 (`units`)
- `id`: INTEGER PRIMARY KEY AUTOINCREMENT
- `name`: TEXT NOT NULL UNIQUE (支行/单位名称)
- `display_order`: INTEGER DEFAULT 0
- `is_active`: INTEGER DEFAULT 1 (1:启用, 0:停用)
- `created_at`: TIMESTAMP DEFAULT CURRENT_TIMESTAMP

### 4.3 投票审计日志表 (`vote_logs`)
- `id`: INTEGER PRIMARY KEY AUTOINCREMENT
- `unit_id`: INTEGER NOT NULL (所属支行 ID)
- `unit_name`: TEXT NOT NULL (历史快照冗余：支行名称)
- `voter_name`: TEXT NOT NULL (投票人姓名)
- `visitor_id`: TEXT NOT NULL (FingerprintJS 设备指纹)
- `client_ip`: TEXT NOT NULL (真实来源客户端 IP)
- `user_agent`: TEXT (客户端浏览器标识)
- `candidate_id`: INTEGER NOT NULL (投票关联的作品 ID)
- `is_valid`: INTEGER DEFAULT 1 (1:有效票, 0:已作废)
- `created_at`: TIMESTAMP DEFAULT CURRENT_TIMESTAMP

### 4.4 唯一约束与索引
- **设备防重**：`CREATE UNIQUE INDEX idx_valid_visitor ON vote_logs(visitor_id) WHERE is_valid = 1;`（同一设备只能有 1 张有效票）
- **实名防重**：`CREATE UNIQUE INDEX idx_valid_unit_voter ON vote_logs(unit_id, voter_name) WHERE is_valid = 1;`（同一支行同一姓名只能有 1 张有效票）

## 5. 部署与运维规范
1. **宿主机环境**：腾讯云 4C4G Linux 服务器。
2. **端口分配**：
   - 容器服务暴露端口：`8090`。
   - 宿主机 Nginx 监听 80/443 并通过 `proxy_pass http://127.0.0.1:8090` 转发。
3. **数据挂载目录**：
   - 数据库：`./data/voting.db`
   - 视频资源：`./docs/videos/`
   - 封面图片：`./docs/covers/`
